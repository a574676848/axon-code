# Axon 安全基线

本文件定义 Axon 在「本地同机」与「云端远连」两种部署下的安全基线：连接形态与地址分流、TLS 与信任来源、两级身份与凭据、上传与路径校验、调试面与日志审计。配置键的完整语义见[配置参考指南](./configuration.md)，网关路由与监听地址见 [Daemon 后台守护进程](./daemon.md)。

程序本身**不做网络层限制**：要不要 TLS、把两个协议面绑到哪块网卡、对外开放到哪一层，全部由部署方的网络与运维配置决定。代码能配置、链路能通，就能连上。

## 1. 连接形态与地址分流

### 1.1 客户端只填一个地址

桌面端只收一个 HTTP 地址（域名或 IP 加端口）。事件流地址不再要求用户填写，由后端自报：

```text
1. GET http://<host>:<httpPort>/api/v1/meta          取能力位与服务器时间
2. GET http://<host>:<httpPort>/api/v1/system/status 取后端自报的 webSocketPort
3. ws://<host>:<webSocketPort>/gateway/v1/ws         事件流
```

主机沿用用户填写的那一个：后端绑定 `0.0.0.0` 时它自己不知道对外可用的 IP，只有客户端知道。

解析顺序固定为「先按同一端口试，再用自报端口校正」：两者共用一条监听时第一步就成立；分成两条监听时第一步在 HTTP 端口上取不到 `/gateway/v1/ws`，随即用自报端口重试。两步都失败才报「事件流端口不对」，并且「测试连接」与「保存档案」都会拦住，不会落下一份「配置能连、事件收不到」的档案。

### 1.2 两个协议面是两条独立监听

| 配置键 | 默认值 | 承担的路由 |
|---|---|---|
| `remote.gateway.http_bind` | `127.0.0.1:3143` | `/api/v1/*`、`/gateway/v1/events*`、`/gateway/v1/interactions/*`、`/api/v1/voice`（语音上行的 WebSocket 与 HTTP 同口） |
| `remote.gateway.websocket_bind` | `127.0.0.1:3144` | `/gateway/v1/ws` |

两个端口由配置决定，因此客户端**不能**从 HTTP 地址推出 WebSocket 端口，只能由后端在 `GET /api/v1/system/status` 的 `webSocketPort` 里自报。这也意味着运维改端口不需要改客户端。

### 1.3 失败必须分三类判定

| 结论 | 判据 | 修复动作 |
|---|---|---|
| 凭据不匹配 | HTTP 401 或 403 | 换凭据或重新签发 |
| 证书有问题 | TLS 握手失败：根不受信、主机名不符、证书过期、链不完整 | 修证书链或换信任来源 |
| 连不上 | DNS 解析失败、连接被拒、连接超时、读取超时 | 查网络与监听 |

三者在协议栈上处于不同阶段，可以分离；不得把证书错误并入「连不上」，否则运维会在错误的层面排查。

### 1.4 部署侧要做的事

以下是部署方的职责，程序不代为判断，也不提供开关：

- 按需要把 `http_bind` 与 `websocket_bind` 绑到 `0.0.0.0` 或指定网卡，并在主机防火墙上分别放行这两个端口。绑定 `0.0.0.0` 会覆盖本机全部网卡（含无线网卡、热点与虚拟网卡），来源范围由防火墙限定。
- 需要 TLS 时在链路里放一个终止点（任何形态均可），并把证书链完整下发。daemon 自身不承担 TLS，客户端也没有「忽略证书错误」开关。
- 明文链路必然让凭据以明文过网，是否接受由运维判断；连接详情里对明文地址常驻一条提示，但它不构成拒绝。
- 凭据强度与轮换周期由运维决定，见第 5 节。

## 2. TLS 落点与桌面端信任来源

云档案的能力完全依赖一条可信的 TLS 链路：凭据在 header 里过网，链路不可信等于凭据可被替换。

### 2.1 证书链由平台根验证

桌面端必须使用平台根证书库，而不是编译期打进二进制的 Mozilla 根集合：

- **HTTP 一侧**：`ureq` 启用 `platform-verifier` feature，构造 agent 时切换到平台验证器。
- **WebSocket 一侧**：`tokio-tungstenite` 没有对应的 feature，只有 `native-roots` 与 `webpki-roots`，因此必须自建 `Connector::Rustls(Arc<ClientConfig>)`，并直接依赖 `rustls` 与 `rustls-platform-verifier` 两个 crate，同时保证与既有 crypto provider 一致。

**`rustls-tls-native-roots` 与平台验证器不等价**：前者只读取根证书文件，不执行平台策略校验（企业策略、证书钉扎、吊销策略等）。两者不得混用后声称行为一致。

不做这件事的后果很具体：企业 TLS 中间盒下，供应商侧联通（走平台验证器），网关侧握手失败（只信编译期根），同一台机器表现为「模型能调通、网关连不上」。放宽或关闭校验都不是可接受的替代方案。

## 3. 鉴权：两级身份

### 3.1 超管与普通 Key

| 级别 | 凭据 | 权限 |
|---|---|---|
| 超管 | 全局 token，即 `remote.gateway.api_token_env` 指向的环境变量，与 daemon 鉴权同一把 | 全部业务路由，以及 `/api/v1/keys` 管理面 |
| 普通 | 由超管签发的任意一把 Key | 全部业务路由；调用 `/api/v1/keys` 一律 403 |

鉴权层返回身份而不是布尔值：路由据此分级，管理面只接受超管。`/meta` 的 `superAdmin` 字段告诉客户端本次请求所用凭据是不是超管，客户端据此决定是否渲染密钥管理入口。

### 3.2 没有免鉴权面

`/api/v1/*` 全部经同一条分派入口处理，鉴权在路由层无条件执行，adapter 拿不到豁免权。因此 `/meta` 同样需要鉴权，不存在「探活免鉴权」的口子。

### 3.3 管理面禁止查询串通道

`/api/v1/keys` 只认 `Authorization: Bearer <token>`：

- 查询串通道会把超管 token 留在各级访问日志、浏览器历史与采集系统里，泄漏面不可控；
- 管理面一旦接受查询串，等于把「能签发一切」的根凭据降级成一段可被邮寄的 URL。

业务面的 `?api_token=` 属历史兼容通道，服务于无法配置 HTTP header 的发送方（典型是只允许填 URL 的 Webhook 配置界面）。它不做百分号解码，token 必须由 URL 安全字符构成，且只应在受信内网或反向代理之后使用。

## 4. 多 Key 的存储事实

- **专用文件**：存于后端运行时根下的专用文件，路径由 `remote.gateway.auth_keys` 指向。不写 `config.toml`，不与状态文件混放。
- **权限 0600**：仅属主可读写；Windows 上按等价 ACL 收口，不授予其他用户与 `Everyone`。
- **只存哈希**：每把 Key 独立盐加强哈希，文件里不存在明文；签发时明文只在回执里出现一次，界面明确提示「离开此页后无法再看」。
- **每条记录带 label、`created_at`、`last_used_at` 与前 6 位指纹**。列表接口只回这几项，不含哈希与明文。
- **`last_used_at` 在鉴权命中时异步更新**：写入不阻塞请求路径，避免每条带鉴权的请求都同步落盘。
- **吊销即失效**：吊销后同一把 Key 立即 401，其余 Key 不受影响。
- **客户端存储走操作系统凭据库**；凭据库不可用时显式失败并退化为 `SessionOnly`（仅本次会话内存），严禁明文落盘。
- **审计**：每次签发与吊销记一行，包含时间、label、来源 IP 与发起方身份；不记明文与哈希。

密钥管理有三条入口，围绕同一套两级身份：CLI（`axon gateway key create/list/revoke`，供运维在服务器上直接操作）、HTTP（`/api/v1/keys`）、桌面端「连接」分区（仅超管凭据时渲染，普通 Key 连接时整块不渲染）。

## 5. 超管凭据的高危性

全局 token 从「单一访问凭据」升格为「能签发一切的根凭据」，处置要求如下：

1. **只存 `.env`**：即配置相邻环境文件，由 `remote.gateway.api_token_env` 指定的变量承载。不得落到客户端档案或客户端凭据库的副本里；客户端按需输入一次即可，必要时走 `SessionOnly`。
2. **禁止经查询串传递**：管理面与业务面一律优先 `Authorization` 头。
3. **泄漏等于后端完全失守**：拿到它即可读取全部配置与密钥状态、遍历服务器文件、签发任意数量的普通 Key，并借助后端执行 shell。这类泄漏应立即轮换，不评估「影响有限」。

轮换顺序（每一步都可执行）：

```text
1. 生成新的高强度随机值
2. 写入 .env 中 remote.gateway.api_token_env 指向的变量
3. 重启 daemon，使新值生效
4. 更新所有客户端档案的凭据（或改填超管签发的 Key）
5. 吊销轮换前签发的全部 Key，并核对列表只剩本次新签发的条目
```

轮换期间不要把明文贴进工单、聊天记录、CI 变量或 shell 历史；需要传递时用凭据库或一次性安全信道。

## 6. 旧 token 的退役策略

- 退役开关是 `remote.gateway.legacy_token_enabled`，**默认 true**，即默认不退役。
- 关闭前必须由使用者确认，并在界面与文档里写明后果。
- 理由只有一条：**本地档案的凭据就是这把 token**，它与 daemon 鉴权同一把，自动退役会让本地档案立刻 401。
- 关闭的前置条件是所有客户端档案改用超管签发的 Key，并且确认没有仍依赖旧 token 的发送方。
- 关闭后必须验证两件事：旧 token 返回 401；**存在 Key 时本地档案仍可连接**。

## 7. 上传校验与上限

| 概念 | 值 |
|---|---|
| 文件字节上限 | 64 MiB（67108864），即 `/meta` 的 `uploadLimitBytes` |
| 附件路由请求体上限 | 64 MiB + 8 KiB（67117056），为 multipart 分隔符与各段头部留固定开销 |
| 未登记路由的统一正文上限 | 4 MiB，不回落 router 级取值 |

界内与界外的判定方式必须分开：

- 有 `Content-Length` 且超过该路由上限：**在读体之前**返回 413，内存不随声明体积增长。
- 有 `Transfer-Encoding: chunked` 而没有 `Content-Length`：返回 411 Length Required，因为服务端无法在收体前确认长度。
- 既无 `Content-Length` 也非 chunked：视为无正文，按 0 处理，不报错（`GET`、`HEAD`、`DELETE` 因此不受影响）。
- 声明长度未超、但文件字节超限：在**读体过程中**判定并返回 413，且不落盘。这一条是「64 MiB + 1 字节」的边界：它的请求体约 64 MiB 加数百字节，低于「加 8 KiB」的门槛，提前判定不会触发。

其余校验要求：

- 上传目录不与任何工作区目录重叠。
- 服务端独立校验类型、越界与压缩炸弹，不信任客户端声明。

验收口径固定为四条：

1. 64 MiB 文件成功；
2. 64 MiB + 1 字节在读体过程中 413 且服务端不落盘；
3. 声明 128 MiB 在读体前 413；
4. 三者都不得让进程 RSS 随声明体积增长。

## 8. 路径归一化与越界拒绝

### 8.1 不引入根集合白名单

不提供 `allowed_roots`、`browse_roots` 之类的配置键，也不按档案模式或请求来源区分注册策略：云端与本地用同一套控制，属正确性而不是策略层。

### 8.2 必须做的事

- 注册与目录浏览一律**先归一化**，再与注册表里的规范化绝对根比对。
- 归一化口径统一：Windows 大小写不敏感、展开 8.3 短名、解析 junction 与符号链接、去掉 `\\?\` 前缀。
- 拒绝而非放行的形态：`..`、绝对路径跳出、NTFS 数据流、设备命名空间、UNC、驱动器相对路径、尾随点与空格被系统剥离的变体。
- 附件目录自成一类根，**不得被当作工作区根**，否则附件可被当源码浏览。
- 服务端路径归一化必须自写实现：仓库里授权由调用方负责的工具不可复用，客户端那份 `resolve_within` 明确禁止复用（它按本机预览语义放行任意绝对路径与 `~` 路径，只对相对路径保留工作区边界）。

### 8.3 已知残余风险：注册即信任

**「已登记工作区根」不是安全边界。** 任何持有效凭据者都能把任意绝对路径注册成工作区根，包括盘符根。因此本基线不承诺「越界注册」会被拒绝，只承诺归一化正确与附件目录不被当作工作区根。

这条风险按已知残余风险登记，不作为待修缺陷处理，理由是：**持有效凭据本身已经等价于可在后端执行 shell**，读文件不是新增特权。缓解手段落在凭据发放环节：按最小必要签发 Key，云端部署据此评估可发放范围与吊销流程，而不是指望路径校验拦人。

## 9. 调试桥

桌面端带一个本地调试桥，由 `--serve <端口> [静态目录]` 显式启动：绑定回环地址、零鉴权、分派表覆盖全部命令。它的响应契约只有 `200` 加 `{ok: false, error}`，没有状态码通道，因此不能用「返回 403」来拦。

要求：**云档案生效时拒绝启动**，以非 0 退出码结束并打印固定中文原因，不做「启动后拒绝转发」。原因很直接：零鉴权桥一旦在远端可及，等于把全部 IPC 命令挂到公网上，而云档案正意味着这台机器连着远端后端。

调试桥只用于本地档案下的浏览器等价验证；验证结束必须关闭调试端口，不得把它带进日常使用。

## 10. 日志与审计

### 10.1 不得记录的内容

- Key 明文、超管 token 明文，任何形式的凭据原文。
- 完整 URL 查询串：其中可能带 `?api_token=`，属历史兼容通道。
- 完整的请求行（含查询串）：部署方自建的中间层若记录访问日志，必须把查询串剥掉。

### 10.2 链路中间层

链路里若存在部署方的中间层（TLS 终止点、网关或采集系统），日志格式由部署方配置，本基线只给口径：

- 访问日志只保留方法、规范化后的路径与状态码，不要记录完整请求行。
- 采集侧沿用同一口径：要么不采访问日志，要么在采集侧再剥一次查询串。
- 管理面一律只用 `Authorization` 头，凭据不进 URL，因此管理面日志不会带出凭据。

### 10.3 后端与客户端

- 后端审计只记身份与动作，不记凭据与哈希：签发、吊销各一行（时间、label、来源 IP、发起方身份）。
- 鉴权失败可记来源 IP 与路由，不记请求携带的凭据。
- 客户端日志与错误文案不得回显 Key 明文；试连接的凭据只存在于内存，失败即丢弃，既不写凭据库也不进日志。
