# 核心概念

Axon 的领域设计遵循清晰的抽象边界与单一职责原则。本文档定义系统核心实体、生命周期状态与行为边界，作为跨模块理解系统的单一事实来源（SSOT）。

---

## 1. 统一认知实体 (Unified Assistant Persona)

Axon 对外保持单一、恒定的助理人设。跨平台桌面端、终端 TUI、命令行与飞书远控仅为表现层输入输出通道，不拥有独立人格：

- **Soul (`~/.axon/SOUL.md`)**：定义主代理的用户级角色身份、语气语调与表达风格，属于跨工作区稳定认知。
- **全局准则 (`~/.axon/AGENTS.md`)**：定义用户级全局行为准则与决策基准。
- **工作区指令 (`<workspace>/AGENTS.md`)**：针对特定工程代码库生效的专业特化开发约定。

```text
┌────────────────────────────────────────────────────────┐
│                   统一数字助理人设 (Axon)                 │
├──────────────────────────┬─────────────────────────────┤
│ 跨工作区稳定认知          │ 动态工作区情境特化          │
│ • SOUL.md 人格设定       │ • <workspace>/AGENTS.md     │
│ • 全局 AGENTS 行为准则   │ • 工作区 Memory 技术事实    │
│ • Personal Memory 偏好   │ • 当前 Git 状态与上下文快照 │
└──────────────────────────┴─────────────────────────────┘
```

## 2. 交互信封 (Interaction)

`InteractionRecord` 是所有自然语言输入与系统事件的统一持久化信封：

- **幂等标识 (Idempotency Key)**：保证重复请求（如网络重试或高频输入）在入库时幂等去重。
- **作用域 (ScopeRef)**：区分全局作用域（Global）与特定工程工作区（Workspace）。
- **受众与策略 (AudienceContext & DisclosurePolicy)**：标识当前输入的受众（如单人私聊、群聊），约束敏感信息披露边界。
- **回复路由 (ReplyRoute)**：记录执行结果应回流的目标渠道与地址（桌面窗口、终端输出或特定飞书会话）。

所有输入必须先经 SQLite 持久化入账，方可进入调度与执行流程。

## 3. 工作承诺与执行实体 (Goal & Execution)

系统严格区分即时对话与长周期工作承诺，并通过事务级状态机管理任务生命周期：

```text
               ┌────────────────────────────────────────────────┐
               │         用户输入 (Interaction Envelope)         │
               └───────────────────────┬────────────────────────┘
                                       │
                                       ▼
                       模型决策边界 (InteractionTurnRunner)
                         /                           \
            (单步答疑/修改) /                             \ (长周期/异步承诺)
                         v                               v
            ┌─────────────────────────┐     ┌─────────────────────────┐
            │   即时交付终态结果      │     │  原子创建持久化 Goal    │
            │  (Direct Answer/Diff)   │     │  (Goal + Execution)     │
            └─────────────────────────┘     └────────────┬────────────┘
                                                         │
                                                         ▼
                                       ┌──────────────────────────────────┐
                                       │     Execution Worker 调度池      │
                                       │  (Lease 租约 · Fencing 防护)    │
                                       └─────────────────┬────────────────┘
                                                         │
                                        ┌────────────────┴────────────────┐
                                        ▼                                 ▼
                             [任务完成: Result]                 [状态未知: Uncertain]
                             (投递回流/通知中心)                 (防重复非幂等保护)
```

- **即时交互 (Interaction)**：代码答疑、单步重构、状态查询等在当前轮次内完成，直接交付结果。
- **持久目标 (Goal)**：当任务需要跨轮次执行、等待外部异步输入或需后台持续推进时，模型生成结构化的 `CreateGoal` 决策，原子创建 `Goal` 实体。
- **执行调度 (Execution)**：代表 Goal 的一次具体调度尝试。拥有独立的 Lease 分布式租约、Fencing 令牌防护、Checkpoint 检查点机制与重试策略。
- **生命周期解耦**：客户端界面关闭不会中断正在运行的 Execution；重新连入后客户端通过游标拉取事件与最新产物。

## 4. 会话车道与运行态窗口 (Lane & Runtime Session)

面向用户的车道设计与底层模型的运行窗口解耦：

```text
 工作区 A (Workspace A)                          工作区 B (Workspace B)
 ├── 车道 1 (Feature: Auth) ───[Session A-1]      └── 车道 1 (Refactor API) ───[Session B-1]
 ├── 车道 2 (Fix: Login)    ───[Session A-2]
 └── 车道 3 (Cron: Audit)   ───[Session A-3]
```

- **任务车道 (Conversation Lane)**：面向用户的高层会话单元。每个工程工作区下可维护多条平行的任务车道，车道间对话历史与上下文完全隔离。
- **运行态会话 (Runtime Session)**：底层 Agent 运行时维系的 Provider 对话历史与工具执行窗口。由当前工作区车道自动派生与复用，作为底层内部实现细节，对上层使用者完全透明。

## 5. 分层上下文与记忆系统 (Context & Memory)

为了兼顾长会话连贯性与大模型服务端 Prompt Cache 命中率，上下文采用三层装配架构：

```text
┌─────────────────────────────────────────────────────────────────┐
│ 1. 稳定前缀 (Cacheable Prefix) - 保证服务端 Prompt Cache 命中率 │
│    System Prompt · SOUL.md · 全局 AGENTS 规则 · Personal Memory │
├─────────────────────────────────────────────────────────────────┤
│ 2. 会话历史 (Conversation History)                              │
│    当前车道内已提交并验证的有效交互消息序列                     │
├─────────────────────────────────────────────────────────────────┤
│ 3. 动态尾部 (Dynamic Tail) - 当前轮次动态注入                   │
│    工作区本地 AGENTS · 项目 Skill · Git 状态 · Workspace Memory │
└─────────────────────────────────────────────────────────────────┘
```

### 记忆空间隔离
- **Personal Memory**：用户全局偏好与身份事实，跨所有工作区共享。
- **Workspace Memory**：特定代码库相关的技术决策、架构事实与规约，仅在当前工作区生效。

## 6. 工具体系与二态权限 (Tools & Authorization)

系统内置通用基础工具链，并通过标准协议支持生态扩展：

- **内置工具 (Built-in Tools)**：
  - 文件操作：分页读取、Glob 模式匹配、全局文本/正则检索；
  - 精准编辑：Hashline 校验编辑、整文件新建/覆写（Add File）、多文件原子补丁（PathDiff）；
  - 系统执行：原生 Shell 会话执行与后台作业管理；
  - 交互原语：向用户发起选项式交互问答（`builtin_ask_user_question`）；
  - 目标与计划：Plan 状态机与 Goal 调度管理；
  - 协作委派：轻量子代理委派（`delegate_to_fast`）。
- **二态权限机制**：所有工具调用在执行前进行统一权限裁决，返回 `Allowed`（放行执行）或 `Forbidden`（携带结构化错误拒绝并审计记录）。

---

## 7. 后台守护进程 (Daemon Host)

Daemon 是 Axon 的常驻后台运行核心：

- **统一网关**：暴露 RESTful API 与 WebSocket 事件流订阅端点。
- **车道调度池 (PrimaryTurnService)**：按工作区车道进行排他性任务领取与调度，保证单车道内操作严格串行、跨车道有界并发。
- **自动化托管 (Cron Scheduler)**：定时驱动 Agent 自动化脚本与周期性治理任务。
- **跨渠道投递**：管理长周期任务结果向各端渠道（桌面通知、飞书消息卡片等）的可靠投递。
