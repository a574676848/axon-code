# Axon Desktop 桌面工作台指南

Axon Desktop 是基于 Tauri 2 与 React 19 构建的跨平台桌面 AI 工作台。它秉承高信息密度的工业级极简设计（纯净暖骨白纸质画布、深邃碳墨文字与发丝分割线），与终端 TUI、无头 CLI 共享同一套 Agent Runtime、网关协议、持久化状态机与上下文认知，提供可视化的多工作区治理、任务车道、流式交互与系统级协同能力。

---

## 1. 架构与通信机制

桌面工作台是 **Axon 网关的专属图形客户端**，前端界面与后台执行完全解耦：

```text
┌────────────────────────────────────────────────────────┐
│                 Axon Desktop (Webview UI)              │
│       React 19 + TailwindCSS + 工业级浅色简约设计系统   │
└───────────────────────────┬────────────────────────────┘
                            │ Tauri 2 IPC (Commands & Events)
┌───────────────────────────▼────────────────────────────┐
│                 Axon Desktop Core (Rust)               │
│      IPC 适配层 · 窗口/托盘 · 本地文件关联 · 集成终端  │
└───────────────────────────┬────────────────────────────┘
                            │ HTTP REST / WebSocket Event Stream
┌───────────────────────────▼────────────────────────────┐
│                 Axon Daemon (常驻守护进程)              │
│      Interaction 状态机 · PrimaryTurnService · Worker  │
└────────────────────────────────────────────────────────┘
```

### 端到端通信时序

```text
[Webview 前端]           [Desktop Core (Rust)]          [Daemon Gateway]
      │                           │                             │
      │ 1. 提交输入 (IPC)          │                             │
      ├──────────────────────────>│ 2. HTTP POST 提交交互       │
      │                           ├────────────────────────────>│
      │                           │                             │
      │ 3. 读取历史帧页 (IPC)      │ 4. HTTP GET 历史帧页        │
      ├──────────────────────────>│────────────────────────────>│
      │                           │                             │
      │ 5. 订阅实时尾 (IPC)        │ 6. WS subscribe(resumeCursor)│
      ├──────────────────────────>│<────────────────────────────┤
      │                           │ 7. WS 增量推送              │
      │ 8. axon://conversation    │<────────────────────────────┤
      │<──────────────────────────┤                             │
```

- **数据一律经网关**：桌面端不直接连接 SQLite 运行时数据库，所有工作区、会话、任务与指标数据均经由 Daemon 网关接口（HTTP 与 WebSocket 事件流）获取。
- **单写边界**：后台守护进程独占主执行流与持久状态；桌面端仅负责增量状态投影、本地配置文件原子更新与指令派发。
- **单连接多路复用**：桌面端与网关之间维持单一 WebSocket 长连接，各个车道与子代理通过 `subscribeId` 独立多路复用，避免连接泄漏。
- **历史走帧页，实时走尾游标**：车道正文由 `GET /api/v1/interactions/<interactionId>/events?after=<序号>&limit=<n>` 分页取回（`hasMore` 决定是否续读），读完把 `tailCursor` 交给 WebSocket 订阅；事件通道上因此只出现真正的增量，不再承担整段回放。
- **回放攒批投递**：实时帧与补齐帧仍按 16ms 窗口合并成一批再交给 WebView（批内保序、单批上限 512 帧），避免逐帧注入跟不上时丢帧、会话停在「生成中」；前端展开后仍按逐帧归约。

## 2. 启动与入口

### 标准启动

推荐通过稳定 launcher 启动桌面端：

```bash
axon desktop
```

启动命令由 launcher 转发至当前生效版本目录内的桌面二进制产物，并自动脱离终端独立运行。

### 运行态自检

验证桌面端二进制与本地环境完整性：

```bash
axon-desktop --self-check
```

该命令执行轻量级自检，输出单行 JSON 结果，退出码 `0` 表示校验通过，`1` 表示异常。

## 3. 核心界面布局

工作台采用「**左侧导航抽屉 + 中部内容与对话流 + 悬浮胶囊底栏 + 右侧运行时停靠面板**」的经典分栏架构：

### 3.1 导航抽屉 (Sidebar)

- **工作区管理 (Workspaces)**：支持添加本地工程目录、查看 Git 当前分支与未暂存变更计数，支持跨工作区一键平滑切换。
- **任务车道 (Conversation Lanes)**：
  - 每个工作区下可创建多个独立的任务车道，每个车道维护独立的对话历史与上下文窗口。
  - 支持车道重命名、置顶固定（Pin）、拖拽排序与归档管理。
- **自动化任务入口**：直达 Agent Cron 定时任务与调度管理看板。
- **目标看板入口**：紧接在「自动化任务」下方，直达主 turn 建立的目标看板。
- **设置中心入口**：直达模型 Provider 配置、MCP 服务器管理与 Agent Soul / 准则编辑。

### 3.2 对话流与实时投影 (Transcript)

- **流式 Token 投影**：模型生成内容通过 WebSocket 流式推送到前端，实时高亮渲染 Markdown、代码块与差异预览（Diff）。
- **图文与媒体渲染**：
  - 支持 Markdown 内联图片与本地工程相对路径图片实时预览。
  - 支持图片 Lightbox 灯箱全屏查看与缩放。
  - 单张图片读取上限为 8 MiB。取到的字节按 Blob 地址交给浏览器，地址跟着持有者回收：滚出视野、卡片撤掉、灯箱关上都会把地址还回去，看不见的图不会继续占着界面内存。
- **内存友好型折叠机制**：
  - 最近两轮（正在跑的一轮与上一轮）始终展开：发送新一轮不会把上一轮收成动作摘要，刚看完的上下文还在原位。更早的轮次才按体量与保留窗口折叠，窗口见 `docs/skills/operate-axon/references/desktop-app.md`。
  - 折叠会释放大体积工具输出与推理正文的界面内存占用，点击时实时按 Interaction 标识按需拉取还原。
  - 正文只挂载末尾窗口内的单元（240 个），更早的整轮折算成「更早的 N 条内容已折叠」；窗口之外的轮次不参与重建，流式追加的代价因此只落在真正变化的那一轮上。

### 3.3 交互式问答卡片 (Interactive Question Cards)

当 Agent 执行遇到关键决策、信息缺口或需用户人工确认时，通过 `builtin_ask_user_question` 触发交互卡片：

- **多形态输入支持**：支持单选、多选以及自由文本输入；已选中的选项再点一次即取消选择（取消会保留已填写的自定义回答），作答草稿随卡片收起与唤回一起保留。
- **有界倒计时与分级预警**：卡片展示倒计时读秒，剩余时间 <= 30 秒进入琥珀色预警，<= 10 秒进入红色警报。
- **进入会话即自动唤醒**：还没答完的提问（等待中、等待延长或已挂起）在打开这条会话时自动占住输入坞，右上角按状态显示读秒或「已挂起」，不需要先去时间线上找入口。收起卡片只在本次进入会话内有效，换到别的会话再回来时卡片重新占位。
- **自动挂起与唤醒机制**：
  - 若用户在预算内作答，回答作为工具返回值直接灌回当前轮次继续执行。
  - 若超时未作答，当前任务自动安全挂起（释放执行锁定并展示挂起提示），卡片继续占位；用户后续随时补填提交后，系统将自动唤醒 Agent 接着未完成的步骤继续推进。

### 3.4 悬浮输入坞 (Composer Dock)

- **多行输入与自动伸展**：正文最多撑到 6 行，超出部分由输入框自己滚动；输入坞长高一行，正文视口就矮一行。输入法组合期间的拼音串不参与量高度（它是输入法的中间态），因此中文输入时上方正文不会被每一下折行顶得上下跳，确认之后才按正文量一次。
- **智能上下文引用**：支持 `@` 快捷键引用工作区特定文件、目录或符号进入上下文。
- **技能指令补全**：输入 `/` 弹出已安装技能候选（左侧指令名、右侧说明，上下键选择，Enter 或 Tab 采纳，Esc 与 Shift + Tab 收起）。候选以浮层贴在输入坞上方，展开与收起都不改变输入坞版面；`@` 与 `/` 共用这一套候选菜单。
- **内置指令**：`/mcp` 重新加载 MCP 服务器列表（清健康负缓存并重连一遍）。按下回车即刻进入指令执行态：输入坞上方给进行态转圈、`正在重载 MCP 服务器…` 与已耗时，返回后换成一行回执并在输入坞上沿摊开清单：加载成功的列出服务器名与工具名，失败的列出服务器名与失败原因（失败项排在前面）。只有正文恰好是这一条指令时才生效，`/mcp 带参数` 按普通消息发给模型。指标条辅助簇常驻 MCP 台数，有服务器没加载起来时整段转危险色；MCP 段右侧紧接技能条数（`技能 12`），与设置 › 技能页读同一份已安装清单，清单未就绪或零条时不占位。
- **技能指令高亮**：正文里精确命中已安装技能名的 `/name` 会在输入框与用户消息气泡里点亮（路径与随手写的斜杠不算），与提交后后端认的是同一份技能名单。
- **网址占位**：粘贴 http 或 https 地址时，草稿里换成 `[站点]` 占位符并在输入框上方给一张链接卡（与原地址同一份完整内容）；提交时展开回原始地址，模型拿到的仍是一个完整 URL。用户气泡里的地址同样收敛成一枚可打开的链接芯片，复制与重新发送都取消息原文。
- **仅附件消息**：不写正文、只带附件也能直接发送。附件路径随消息一起交给模型，气泡里只显示附件卡、不显示额外文字；发送失败后点「重新发送」，附件同样跟着重发。
- **语音听写与朗读（当前入口隐藏）**：本机语音模型已移除，识别与合成改由云端提供方承担；提供方接入前输入坞不显示麦克风、顶栏不显示自动朗读开关、消息不显示朗读按钮、设置与人设页不显示语音配置（`ui/src/speech/enabled.ts` 的 `VOICE_UI_ENABLED`）。恢复入口后的形态：输入坞内置原生语音入口，宿主自动接管本地应用源的 WebView 媒体授权并消除浏览器式地址栏弹窗，遇系统级麦克风隐私拦截时提供应用内原生引导与一键打开系统麦克风设置；说话期间输入坞上方给出一条录音条（实时声波、计时、条内直接显示识别中的文字）；定稿只写进输入框、不直接发送，再点麦克风或按 Esc 即关闭（语音开着时的 Esc 只关语音，不打断正在进行的回复）；单次录音上限 120 秒自动停止，点麦克风前会先确认 `GET /api/v1/voice/status` 的 `runtimeAvailable`；助手消息底部与顶栏支持单条朗读及会话级自动朗读。
- **思考强度与模型切换**：输入坞实时展示当前生效的基座模型与 Reasoning Effort（思考强度），支持就地快速调整。
- **执行打断 (Interrupt)**：任务进行中输入坞提供显式打断按钮，安全中断当前轮次执行并保护现场数据。

### 3.5 运行时停靠面板 (Runtime Drawer)

- **子代理跟踪 (Subagents)**：以树状拓扑实时展示后台运行的并发子代理状态、任务目标、Token 消耗与执行进度。
- **后台作业监控 (Background Jobs)**：实时查看后台 Shell 命令执行状态，支持实时 stdout/stderr 日志流查看与一键终止进程（Job Kill）。
- **工作区文件浏览器**：右侧内置工程文件轻量树状查看器，支持源码只读快速浏览、复制路径以及调用操作系统默认应用（Open with...）打开。
- **集成终端 (Integrated Terminal)**：支持在当前工作区目录下快速开启本地终端命令行，与 AI 编程形成同屏协同。

### 3.6 目标看板 (Goals)

对话中通过 `builtin.goal_*` 建立的目标在侧栏「目标看板」里以卡片看板呈现，事实全部经网关的只读 goals 面读取，桌面端不直连运行态数据库。

- **四栏看板**：待开始 / 进行中 / 已暂停 / 已结束；等待中与进行中同栏，卡片以状态点与语义状态胶囊区分。栏目栅格按容器宽度从一列逐级加到四列，顶部对齐。
- **卡片信息**：标题、语义状态标签、去重后的目标预览、结构化进展带（下一步或等待原因）、工作区与最近活动时刻，右下只有一个入口；入口文案与实际动作一致，写「进入会话」就进会话，写「查看详情」就开详情。
- **筛选与搜索**：搜索支持一键清空，覆盖标题、目标预览、工作区与下一步；状态分段为「全部 / 未完成 / 已结束」，计数与卡片同源；筛选无匹配时提供一键清除筛选空态。
- **渲染上限**：每栏最多渲染 20 张卡片，超出时给「显示其余 N 个」；初始挂载上限 80 张，展开后仍受服务端 256 条上限约束，计数旁写明「已达上限，仅显示 256 个」。
- **静默刷新**：存在未完成目标时每 4 秒刷新一次，全部进入终态即停止；请求串行化、旧响应不覆盖新响应；窗口隐藏时跳过本轮，恢复可见后下一拍自愈；失败不弹窗，连续失败才由页面错误条说明。
- **执行会话视图**：点开卡片进入该目标的执行会话（全局目标的工作区由详情解析，因此卡片先落到详情，再由详情给出进入入口），逐字稿与主会话同一条管线（同一份 durable 事件流、同一个归约器、同一套渲染）。视图采用 40px 可拖拽顶栏（支持 `Esc` 返回与查看目标详情），目标概览卡与逐字稿共用 840px 居中阅读列宽，展开可查看完整目标、序号化步骤与验收清单，超出服务端上限时如实标注截断；视图只读，不渲染输入坞。
- **状态呈现**：空态、加载、读取失败、目标已被清理与旧版后台（含「网关不含该接口，后台服务版本可能过旧」）都有正式呈现，不伪造空会话。
- **焦点连续性**：进入会话视图焦点落到返回按钮，返回后回到来源卡片。

### 3.7 记忆管理

- **类型与范围**：按画像、偏好、经验、知识、流程五栏组织；作用域可选全部可见记忆、个人记忆或某个真实存在的仓库，`~/.axon` 会以「Axon 主目录」出现在同一个下拉里。
- **归档状态**：工具栏的「活跃 / 已归档 / 全部」分段决定时间轴窗口，默认只列活跃记录；页签计数与当前窗口同口径，不会出现页签写着 5、列表只有 4 的读数打架。
- **条目操作**：修改（写入新版本并建立替代关系）、归档或取消归档（只切换归档位，正文保留，取消后重新参与召回）、永久删除（带确认弹窗）。已遗忘的记录正文与引用已清除，只保留永久删除。
- **状态标签**：已归档、已遗忘与已隔离在条目行首并列显示；顶部三联读数分别是总记录、活跃与已归档。

## 4. 设置与配置中心

通过左侧栏底部设置入口，支持对 Axon 运行态进行可视化治理：

1. **基础设置**：
   - 配置文件 `config.toml` 表单化读取与安全验证。
   - 原子更新（保存前通过临时文件校验，避免进程异常损坏配置）。
   - 支持直接在系统文件管理器中打开配置文件所在目录。
2. **模型与供应商 (Providers & Models)**：
   - 可视化添加、修改与移除 Provider 配置（如 OpenAI、Anthropic、DeepSeek、Ollama 等）。
   - API 密钥安全掩码管理，明文密钥隔离保存在环境变量中，前端绝不持有或持久化明文凭据。
   - 支持一键在线探查上游可用模型列表。
   - 模型行提供「回传推理内容」开关：思考模式网关要求历史助手消息逐条携带推理内容时开启，缺失时补空串，仅对 OpenAI Chat Completions 生效。
3. **扩展中心 (MCP & Skills)**：
   - 可视化查看已加载的 Model Context Protocol (MCP) 服务器列表、工具定义与启停状态。
   - 查看与探查用户级与工作区级 Skill 技能清单及其 `SKILL.md` 规范。
4. **用量统计 (Usage)**：
   - 经网关 `/api/v1/observability/*` 读取统计事实，桌面端不直连 `usage/usage.sqlite3`。
   - 概览读数（请求数、Token、缓存命中率、成功率、RPM/TPM、成本）与迷你走势。
   - 用量趋势（Token 五类构成、请求数、成本三种读法切换），缺数据的时段留空档。
   - 实时吞吐与滑窗 Token 构成（15 / 30 / 60 分钟窗口）。
   - 模型或供应商维度的用量排行（Token 占比、请求数、缓存命中率、成本）。
   - 活动日历（按天活跃度）与请求健康时间线（按小时终态）。
   - 延迟诊断（分位阶梯与首字延迟对总耗时的散点，窗口上限 7 天）。
   - 请求事件日志（模型 / 来源 / 结果过滤，游标分页）。
   - 未定价的成本如实显示为「未定价」：Axon 不预设模型价格，配置价格规则后才有金额。
5. **模型定价 (Pricing)**：
   - 价格规则清单：模型匹配式、计费风格、四项单价（美元 / 百万 Token）、倍率与优先级，支持搜索与分页。
   - 新增、编辑与删除规则；编辑采用先建后删，中途失败时原规则保持不变。
   - 一键从 models.dev 同步费率，或按当前规则重算已落库的历史成本。
   - 每日自动同步开关：打开时创建或启用系统 Cron 任务 `axon.system.pricing-sync`（每天一次），关闭时转为暂停并保留运行记录。
6. **Agent 人格与规则 (Soul & AGENTS)**：
   - 可视化编辑 `~/.axon/SOUL.md`（定义主代理人设）与全局 `AGENTS.md`（行为准则）。
设置 › 人设 顶部展示当前形象与身份：形象照来自 `~/.axon/persona/art-halfbody.png`，经网关 `GET /api/v1/persona/portrait/<file>.png` 以 Base64 返回，桌面端不直接读文件；缺失时显示「未放置形象」占位。
   - 人设分区顶部另有一块只读的人格状态面板：内核解析结论、持久化状态、最近转移与已发布习得风格，数据经网关 `/api/v1/persona/summary` 读取。
   - 保存时附带 Prompt Cache 影响提示。
7. **自动化任务 (Cron Scheduler)**：
   - 图形化创建与维护 Agent 定时任务（支持 interval/cron/once 语法）。
   - 分页查看定时任务执行历史、耗时与回执。
8. **系统设置（桌面外壳与运行状态）**：
   - 桌面端自身偏好（三套界面主题「纸白 / 冷杉 / 黑曜石」实时切换、消息通知开关、语音播报开关与语音输入设备选择；设备候选来自系统枚举，试听只读实时电平不录音）。
   - 运行状态面板：Daemon 结论（运行中 / 后台已停机 / 运行受限 / 未运行）、后台租约与排队读数（待领取、处理中、待投递）、网关各面监听、飞书远控与配置目录。
   - Daemon 一行内置重启图标：点击即重启后台服务，界面结论以重启后的真实探测为准，失败原因原样上屏。

## 5. 系统集成与桌面偏好

- **系统通知**：当任务完成、子代理执行完毕或交互问答等待用户输入且窗口未聚焦时，发送原生桌面系统通知。
- **系统托盘**：最小化至托盘常驻，托盘菜单提供快速呼出、状态查看与退出选项。
- **全局快捷键**：`Ctrl + Alt + Space` 由宿主注册为系统级热键，唤回窗口后把焦点交给输入坞；组合键被别的应用占用时只在日志留一行，不影响启动。
- **网关健康感知与自愈**：探活先判端口监听，再用一次带鉴权的真实接口调用确认协议；单轮预算 5 秒并退避重试一次。从已连接掉下来要连续两轮失败才切换成未连接态，单轮超时只记瞬时，因此本机被构建或测试占满时不会把界面翻成离线。确认为未连接后，界面用同一份面板给出结论、网关地址、服务状态（端口是否监听、连续几轮无响应）与可执行的修复动作，主区域保留同样的结论而不是留一片空白。界面能连上但会话不再被领取的后台停摆（网关应答、租约失效），由「设置 › 系统设置 › 运行状态」给出结论与重启入口。
- **窗口材质**：Windows 11 启用 DWM Mica，macOS 启用 `Sidebar` Vibrancy，托盘底座在窗口激活且未最大化时透出系统材质的微弱漫射光；Windows 10 与 Linux 直接回退 100% 实色托盘，不使用有重绘拖影的 Acrylic。材质结论由宿主在首帧就绪时回执，前端据此决定半透或实色。
- **窗口四角**：由托盘底座自己裁 10px 圆角（窗口本体透明，四角透出桌面），只在系统材质生效时开启、最大化时归零；不调 DWM 的圆角属性，因为它需要 `unsafe` 调用，而本工作区禁止 `unsafe_code`。
- **启动时序**：主窗口初始不可见，几何状态（尺寸、位置、最大化、全屏）静默恢复后由前端首帧就绪信号触发显示，宿主另有 350ms 兜底超时。启动全程无白底闪烁、无窗口瞬移。
- **窗口状态机**：窗口失焦或最大化时托盘退回实色并停止 DWM 混合采样；最大化状态的翻转由宿主推送单次事件，前端不做 resize 轮询。
- **界面兜底页**：界面每 5 秒经一次 IPC 向宿主报到，宿主记下最后一次报到时间。窗口可见且未最小化时，连续 20 秒没有报到（渲染进程卡死或已被系统回收）就把界面切到随包发布的引导页 `error.html`；进程失败事件同时订阅，进程一死即刻接管，不必等静默。同一现场只切一次，切换后冷却 30 秒。
- **内存看护**：折叠与窗口化都管不住「页面还在响应、内存却被吃光」这一种，因此另有一条内存判据。阈值取物理内存的八分之一并夹在 768 MiB 与 4 GiB 之间，页面渲染进程的常驻集合越过阈值就提前接管，赶在系统回收渲染进程之前把话说清楚。判定只数渲染进程：浏览器宿主与工具进程的常驻集里混着大量与渲染共享的映像页（WebView2 的二进制、V8 快照），逐进程相加会把同一份物理页记上好几遍。每次接管都往 `data/logs/desktop-ui-failure.jsonl` 追加一行分项读数，并把同一组分项带进引导页的「复制诊断信息」，事后能判断是真失控还是口径问题。
