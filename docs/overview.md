# 系统概览

Axon 是为个人与工程创造者量身打造的**专属个人智能体（Personal Agent）与战术协同平台**。系统以“**知你所想，办你所托**”为产品核心灵魂，在跨平台桌面端（Desktop Workbench）、终端全屏交互（Terminal TUI）、无头命令行（Headless CLI）与企业协同接入（飞书长连接）之间，提供具备工业级可靠性的统一 Agent 运行时、智能模型路由、分层认知上下文以及原子持久化状态引擎。

---

## 1. 核心系统架构

系统严格遵循**洋葱架构（Onion Architecture）**设计范式，内部领域层绝对解耦，外部基础设施通过标准端口进行依赖注入：

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│                             统一多端接入层 (Clients & Ingress)                     │
│    桌面工作台 (Tauri 2)  │  终端全屏 TUI (Ratatui)  │  无头 CLI  │  企业协同 (Feishu)    │
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         │ HTTP REST / WebSocket Event Stream
┌────────────────────────────────────────▼─────────────────────────────────────────┐
│                          Axon Daemon 常驻网关与守护进程 (Gateway)                  │
│             排他车道隔离 (Lane Router)  │  长周期自动化调度 (Cron Scheduler)         │
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         │ Durable Transactions (SQLite)
┌────────────────────────────────────────▼─────────────────────────────────────────┐
│                       任务执行与调度中枢 (PrimaryTurnService)                      │
│      Interaction 状态机  │  Lease Fencing 租约控制  │  Execution Worker 并发调度池  │
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         │ Execution Loop
┌────────────────────────────────────────▼─────────────────────────────────────────┐
│                           Agent Runtime 核心执行回路                              │
│   分层上下文装配 (Prefix Cache)  │  二态权限安全拦截  │  轻量子代理委派 (Subagents)     │
└────────────────────┬───────────────────┼────────────────────┬────────────────────┘
                     │                   │                    │
                     ▼                   ▼                    ▼
             [LLM Providers]     [内置原子工具集]      [标准扩展生态]
             OpenAI / Anthropic  文件读写 / 精确补丁  Model Context Protocol (MCP)
             DeepSeek / 本地模型  原生 Shell / 认知记忆 领域技能体系 (Skill.md)
```

## 2. 端到端执行时序

从用户发起请求到结果持久化交付的完整生命周期时序：

```text
[用户客户端]              [Daemon 网关]          [持久化队列]         [PrimaryTurn]        [Model & Tools]
     │                         │                      │                    │                   │
     │ 1. SubmitInteraction    │                      │                    │                   │
     ├────────────────────────>│                      │                    │                   │
     │                         │ 2. 幂等入库落盘      │                    │                   │
     │                         ├─────────────────────>│                    │                   │
     │                         │                      │ 3. 排他认领车道    │                   │
     │                         │                      ├───────────────────>│                   │
     │                         │                      │                    │ 4. 上下文装配与调用│
     │                         │                      │                    ├──────────────────>│
     │                         │                      │                    │ 5. 流式 Token / 工具│
     │                         │                      │                    │<──────────────────┤
     │ 6. WebSocket 事件推送   │<──────────────────────────────────────────┤                   │
     │<────────────────────────┤                      │                    │                   │
     │                         │                      │ 7. 提交终态回执    │                   │
     │                         │                      │<───────────────────┤                   │
```

1. **统一持久化信封**：所有交互输入首先通过 `SubmitInteraction` 写入 SQLite 持久化队列，确保即使客户端意外离线或网络闪断，任务亦不丢失。
2. **车道排他认领 (Workspace Lane)**：调度中枢基于 `Workspace + Channel + Destination` 车道哈希进行排他认领，保障同一工作区内的操作严格有序、跨工作区操作高并发隔离。
3. **分流执行决策**：
   - **即时交互 (Direct Interaction)**：问答、局部代码修改和即时查询在当前轮次内直接交付，完成流式输出并记录 Interaction 终态。
   - **长周期工作承诺 (Goal & Execution)**：当识别到任务需跨回合推进、异步等待或后台托管时，模型生成结构化的 `CreateGoal` 决策，原子创建 `Goal` 实体及首个调度 `Execution`，交由后台 Execution Worker 池持续推进，用户重新连接后可通过游标重放（Cursor Replay）无损获取结果。

## 3. 持久化状态模型

系统采用 SQLite 作为单一事实源（SSOT），实体设计具备高内聚性与严谨的生命周期约束：

- **Interaction（交互信封）**：自然语言输入的权威凭证，记录来源、时间戳、工作区作用域与受众回复路由。
- **Goal（工作承诺）**：跨轮次、异步等待或长周期任务的持久契约。
- **Execution（调度实体）**：代表 Goal 的具体可调度尝试，内置分布式租约（Lease）、防幽灵锁隔离令牌（Fencing Token）与重试状态机。
- **Result & Event（事实流水）**：不可变的执行产物与领域事件序列，支持离线追溯与事件回放。
- **Runtime Session（会话窗口）**：底层模型推理维系的有界上下文运行态，作为系统内部机制对上层保持透明。

## 4. 上下文装配与分层记忆

为兼顾长会话的记忆延续性与大模型服务端 Prompt Cache 的缓存命中率，模型请求严格遵循分层装配规范：

```text
┌────────────────────────────────────────────────────────┐
│  稳定前缀 (Cacheable Prefix) - 命中率最大化              │
│  System Prompt · SOUL.md 人设 · 全局准则 · 个人记忆     │
├────────────────────────────────────────────────────────┤
│  会话历史 (Conversation History)                       │
│  当前车道已确认提交的有效轮次消息流                     │
├────────────────────────────────────────────────────────┤
│  动态尾部 (Dynamic Tail) - 按需动态注入                 │
│  工作区准则 · 项目技能 · 运行环境与 Git 状态 · 本地记忆 │
└────────────────────────────────────────────────────────┘
```

- **稳定前缀**：跨项目工作区保持字节级恒定，促成各大模型供应商高达 80% 以上的服务端 Prompt Cache 命中率，大幅削减 API 成本与首字响应延迟（TTFT）。
- **动态尾部**：按需引入特定工程的工作区指令与环境事实，杜绝上下文污染。

## 5. 工具生态与标准扩展

- **内置工程工具**：提供高性能文件定位与编辑（Hashline、Add File、PathDiff）、原生 Shell 会话执行与后台作业管理、全局正则/文本检索、交互式选项问答卡片（`builtin_ask_user_question`）与执行计划状态机。
- **Model Context Protocol (MCP)**：支持业界标准 MCP 服务接入（Stdio 与 SSE 传输），具备动态 OAuth 认证与凭据安全存储。
- **Skill 技能体系**：基于 Markdown Frontmatter 规范的工作流扩展，支持运行时提示词自进化与按需装载。
