# 人格系统

本文是 Axon 人格系统的单一事实源：格式、分层、状态与体积预算都以本文为准，实现不得偏离。

---

## 1. 定位

Axon 对外只有一个人格，桌面端、终端 TUI、命令行与飞书远控共用同一份人设与同一份状态，任何通道都不拥有独立人格。人格只属于主代理：子代理、后台 Goal 执行与自我迭代子代理不装配任何人格片段。

人格由四层组成，与实现一一对应：

| 层 | 职责 | 落点 |
|---|---|---|
| 内核 | 身份、来处、不可违背项、特质、表达基线、场景规则 | `~/.axon/SOUL.md` |
| 感知 | 渠道、受众、时段、是否在 Workspace、距上轮的空闲时长 | 轮前确定性组装，零模型调用 |
| 调度 | 按 owner 持久化的状态机与表达策略 | `~/.axon/data/persona/persona.sqlite3` |
| 表达 | 本轮的语气、正式度、幽默与篇幅 | 动态提示片段 |

---

## 2. SOUL.md 格式

文件位于 `~/.axon/SOUL.md`，由必填 YAML frontmatter 与可选 Markdown 正文组成，`schema` 必须等于 `axon-soul/v1`。旧格式不再识别。

```yaml
---
schema: axon-soul/v1
identity:
  name: Axon（艾克森）
  address: 长官
  role: 长官的首席个人 AI 助理与战术副官
backstory: |
  来处与经历，构成身份深度。
invariants:
  - 依据事实作答，严禁未经验证宣称完成
traits:
  - 沉稳冷静
voice:
  warmth: 35
  formality: 65
  humor: subtle
  verbosity: concise
rules:
  - when: { mode: incident }
    voice: { humor: off, verbosity: minimal }
---
正文补充说明，原样进入稳定段 NOTES 分节。
```

校验规则：

- 文件上限 64 KiB，UTF-8 无 BOM。
- 必填 `schema`、`identity.name`、`identity.address`、`identity.role`、`backstory`、`invariants`（至少一条）、`traits`（至少一项）、`voice`（四个字段齐全）。
- 未知字段一律判无效，不做静默拼写纠正。
- `voice.warmth` 与 `voice.formality` 取 0 至 100；`humor` 取 `off` / `subtle` / `playful`；`verbosity` 取 `minimal` / `concise` / `detailed`。
- `rules[].when` 只允许 `mode` 与 `audience`，且至少声明其一；`rules[].voice` 至少覆盖一个表达字段。

## 3. 模式与状态

轮前按固定优先级推导模式，首条命中生效：

1. 群聊受众 → `group`
2. 连续失败达到 2 次，或用户状态为受挫/紧急 → `incident`
3. 存在 Workspace → `focus`
4. 其余 → `casual`

状态按 owner 一行持久化，字段为：状态版本、温度偏移、熟悉度、上一轮用户状态、连续失败轮数、待纠偏提示、最近变化原因、更新时间。

状态转移的硬规则：

- 每次变化必须带非空原因，否则领域层拒绝写入。
- 群聊轮只读：不写状态，也不采集或发布习得风格。
- 温度偏移夹在正负 20 之间，半衰期 6 小时回归基线。
- 熟悉度仅在一轮私聊正常完成时加一，上限 100。
- 一轮失败或中断使连续失败加一，正常完成清零；失败轮不入治理队列，在失败收口处直接结算。
- 结算幂等：同一轮的同一终态重放不会重复生效。

### 3.1 转移表

| 输入 | 转移 | 原因文案 |
|---|---|---|
| 正常完成 | 连续失败清零；私聊熟悉度加一 | 任务完成 |
| 失败 | 连续失败加一 | 连续第 N 次失败 |
| 中断 | 连续失败加一 | 本轮被中断 |
| 用户状态 positive | 温度偏移加 5（夹在正负 20 内） | 用户反馈积极 |
| 用户状态 frustrated | 温度偏移加 3 | 用户受挫，先致意再解决 |
| 用户状态 urgent | 仅记录状态 | 用户状态紧急，收敛节奏 |
| 漂移达 7000 基点且给出原因 | 写入待纠偏提示，下一轮消费后清除 | 上一轮表达漂移：<原因> |
| 用户手动重置 | 回到基线，版本继续单调递增 | 用户手动重置 |

### 3.2 表达策略求值顺序

固定五步，前一步的输出是后一步的输入：

1. 取人格内核的 `voice` 基线。
2. 按模式套默认：`focus` 幽默降一档；`incident` 幽默关闭且篇幅取 `minimal`；`group` 正式度加 20 且幽默关闭；`casual` 不变。
3. 按声明顺序匹配场景规则，首条命中生效，覆盖对应表达字段。
4. 仅 `casual` 模式叠加衰减后的温度偏移。
5. 安全收敛：深夜时段篇幅不超过 `concise`。

群聊另有两道硬限制：原因固定为「群聊场景」，纠偏提示只给「回归基线」，不带原文。

## 4. 体积预算

| 项 | 上限 | 越线行为 |
|---|---|---|
| 稳定段 | 6144 B | 超过 4096 B 预警；超过 6144 B 按分节优先级收敛 |
| 动态段 | 1024 B | 按字节截断且落在字符边界 |
| 每轮新增输入 token | 300 | 典型值 120 至 160 |

收敛顺序固定为：已发布习得风格、正文、场景规则、来路正文、特质与表达基线。`IDENTITY` 与 `INVARIANTS` 永不截断：两者单独就超过 6144 B 时允许整段超限，由调用方记录告警。

---

## 4.1 习得风格的生命周期

| 阶段 | 规则 |
|---|---|
| 候选 | 评估器仅在私聊轮、且判定为表达风格偏好时给出 `styleCandidate`（不超过 120 字）与证据引用 |
| 校验 | 空白、超长、疑似凭据（`sk-`、`ghp_`、私钥头、`password`、`secret` 等）、与不可违背项重复，一律拒收 |
| 待发布 | 通过校验后写入 `pending`，此阶段不影响提示词 |
| 发布 | 每 24 小时最多一次批量发布；窗口判定在写事务内完成，避免并发穿透 |
| 上限 | 已发布最多 16 条，超出时最旧的自动退役 |
| 退役 | `axon persona style retire <id>` 立即把条目置为 retired，稳定段下一轮即少一条；这是唯一可绕过 24 小时发布窗口的入口，由用户显式触发 |

## 5. 缓存与失败策略

稳定段以独立 session-stable 片段注入，参与 Soul 缓存分段；动态段进入动态尾部且不参与缓存。因此状态每轮变化不影响缓存身份，只有人格内核或已发布习得风格变化才会让它失效。

| 情形 | 行为 |
|---|---|
| 人设文件不存在或为空 | 不装配人格，不报警告 |
| 人设格式无效 | 本轮不装配人格，告警带字段路径，回合继续 |
| 人格库不可用或无 owner | 稳定段照常装配，动态段省略，告警写明原因 |
| 装配耗时超过 50 ms | 放弃动态段，本轮降级并记告警，回合继续 |

除人设文件缺失外，其余告警会随该轮终态进入 `warnings`：CLI 的 JSON 与文本输出直接可见，daemon 托管通道写入 `DaemonRunReport.warnings`。TUI 的逐字流不插入告警行。

## 6. 命令

| 命令 | 语义 |
|---|---|
| `axon persona validate [--file <path>]` | 校验 `SOUL.md` 或指定文件；通过时回报格式与条目数，失败时非零退出码 |
| `axon persona status [--json]` | 展示人设是否有效、`SOUL.md` 内容哈希、库状态、当前状态、最近转移与已发布习得风格条数；`--json` 始终输出结构化读数，库或 owner 缺失时对应字段为 null。内容哈希是文件字节的 SHA-256，不是缓存身份 |
| `axon persona style list [--all]` | 列出习得风格；`--all` 连同待发布与已退役条目 |
| `axon persona style retire <style-id>` | 退役一条习得风格，立即生效 |
| `axon persona reset [--yes]` | 把状态重置为基线；缺 `--yes` 只打印提示不写库，人设文件与习得风格不动 |
| `axon doctor --check persona` | 与 `validate` 同一判定，另加人格库身份检查 |

人设由用户手写，运行时不改写 `SOUL.md`。真正生效的时机是下一次主代理请求，无需重启会话。
