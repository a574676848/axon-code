# 使用统计与成本

Axon 把你每一次请求的用量记录下来，供你在命令行或桌面工作台里查看：花了多少 Token、命中多少缓存、请求成功率、耗时分布，以及按模型或供应商拆分的占比。统计采集在旁路完成，不影响对话与工具执行。

这些数据只保存在本机；费用字段在没有可适用的价格规则时统一显示「未定价」，Axon 不内置任何模型价格表。

---

## 1. 命令行查询

```bash
# 今天的聚合结果与最近请求
axon usage

# 最近 7 天，并立即增量补齐最新记录
axon usage --period 7d --refresh

# 按供应商、模型或调用来源过滤
axon usage --period 30d --provider openai
axon usage --period all --model gpt-5
axon usage --source subagent

# 只统计一条会话或一次运行
axon usage --session <SESSION_ID>
axon usage --run <ASSISTANT_PART_ID>

# 结构化输出
axon usage --period all --format json
```

| 参数 | 取值范围 | 说明 |
| --- | --- | --- |
| `--period` | `today`、`7d`、`30d`、`all` | 统计时间窗口，默认 `today` |
| `--source` | `all`、`primary`、`subagent`、`cron`、`goal` | 调用来源过滤 |
| `--session` | 会话 ID | 按会话精确过滤 |
| `--run` | 单次运行 ID | 按一次运行精确过滤 |
| `--provider` | 供应商名称 | 按供应商过滤 |
| `--model` | 模型标识 | 按模型过滤 |
| `--limit` | 正整数，默认 20 | 返回最近请求明细的最大条数 |
| `--refresh` | 标志开关 | 查询前触发一次增量投影 |
| `--format` | `text`、`json` | 输出格式 |

查询普通窗口时读取预聚合结果，速度快；指定 `--session` 或 `--run` 时改为对该范围实时聚合，保证会话之间严格隔离。

还有三个专用子命令：`axon usage diagnostics` 看延迟分位、散点与模型效益；`axon usage audit` 按游标检索最近 90 天的审计日志；`axon usage export` 把审计日志流式导出为 CSV 或 JSON。

## 2. 桌面看板

入口在「设置 › 用量统计」，分五个页签：概览（读数、趋势、排行）、实时（滑动窗口吞吐与 Token 构成）、活动（活跃日历与请求健康时间线）、诊断（延迟分位与散点）、请求日志（单次请求明细）。周期可选 `today`、`7d`、`30d`、`all`；诊断页固定在上限 7 天的窗口内；实时页每 30 秒自刷新，其余页手动刷新。

生成速率的口径与会话头部一致：分子含推理输出 Token，分母是该轮各条流的实测流式耗时之和减去首字延迟。这与工作台和终端显示的速率是同一个值。

## 3. 模型定价

入口在「设置 › 模型定价」。你可以维护价格规则：模型匹配式、计费风格、四项单价（美元 / 百万 Token）、倍率与优先级。价格只用于成本估算，规则越具体优先级越高。

- 编辑采用先建后删，中途失败时原规则保持不变。
- 可以从 models.dev 同步费率；同步按当前配置里声明的供应商与模型匹配，代理侧常见写法（思考档位后缀、日期戳、厂商前缀）都会归一到规范模型；聚合商加价条目与全零计划条目不参与。手工规则的优先级高于同步规则。
- 每日自动同步开关会在系统里创建或启用一个每天一次的定时任务；关闭时转为暂停并保留运行记录。
- 修改规则不会自动改写已落库的历史成本；需要时显式触发一次历史重算。

配置里的模型别名是路由键，用量事实按模型 ID 记录，因此给渠道起别名不需要额外价格规则，改 ID 才会换一条匹配式。

## 4. 数据保留与重建

用量明细默认保留 30 天，清理只针对已结束的记录。用量数据是从会话记录派生出来的投影，损坏或丢失时可以整体重建，不会丢原始用量事实。查询回执里的 `projection.stale` 字段会提示当前读数是否落后于最新事实。
