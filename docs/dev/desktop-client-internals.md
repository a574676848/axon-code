## 1. 架构与通信机制

桌面工作台是 **Axon 网关的专属图形客户端**，前端界面与后台执行完全解耦：

```text
┌────────────────────────────────────────────────────────┐
│                 Axon Desktop (Webview UI)              │
│       React 19 + TailwindCSS + 工业级浅色简约设计系统   │
└───────────────────────────┬────────────────────────────┘
                            │ Tauri 2 IPC (Commands & Events)
┌───────────────────────────▼────────────────────────────┐
│                 Axon Desktop Core (Rust)               │
│      IPC 适配层 · 窗口/托盘 · 本地文件关联 · 集成终端  │
└───────────────────────────┬────────────────────────────┘
                            │ HTTP REST / WebSocket Event Stream
┌───────────────────────────▼────────────────────────────┐
│                 Axon Daemon (常驻守护进程)              │
│      Interaction 状态机 · PrimaryTurnService · Worker  │
└────────────────────────────────────────────────────────┘
```

### 端到端通信时序

```text
[Webview 前端]           [Desktop Core (Rust)]          [Daemon Gateway]
      │                           │                             │
      │ 1. 提交输入 (IPC)          │                             │
      ├──────────────────────────>│ 2. HTTP POST 提交交互       │
      │                           ├────────────────────────────>│
      │                           │                             │
      │ 3. 读取历史帧页 (IPC)      │ 4. HTTP GET 历史帧页        │
      ├──────────────────────────>│────────────────────────────>│
      │                           │                             │
      │ 5. 订阅实时尾 (IPC)        │ 6. WS subscribe(resumeCursor)│
      ├──────────────────────────>│<────────────────────────────┤
      │                           │ 7. WS 增量推送              │
      │ 8. axon://conversation    │<────────────────────────────┤
      │<──────────────────────────┤                             │
```

- **数据一律经网关**：桌面端不直接读写运行数据，所有工作区、会话、任务、指标、配置、密钥、MCP、技能与文档数据均经由后台服务的网关接口（HTTP 与 WebSocket 事件流）获取。
- **单写边界**：后台守护进程独占主执行流与持久状态；桌面端仅负责增量状态投影、本地界面偏好与指令派发。
- **单一生效连接档案**：桌面端同一时刻只连一个后端，档案（本机或云端）记在客户端自有数据目录里，不写进 `config.toml`。端点解析的有序来源是「运行时生效档案 > 配置文件里的网关监听地址 > 兜底常量」；本机档案每次解析只重读 `http_bind` 与 `websocket_bind` 这两个键，因此改完监听地址不必重启应用。
- **能力位来自后端自报**：连上后取一次 `GET /api/v1/meta`，按其中 12 个能力位决定哪些入口出现；云档案的 `service_control` 与 `terminal` 由客户端强制覆盖为 false（后端不知道自己被谁连接）。没取到能力位时入口可见但置灰，`/api/v1/meta` 缺失（HTTP 404）同样按未连接呈现并提示核对地址与端口，不另做版本推断。
- **TLS 信任来源取平台根**：网关 HTTP 与 WebSocket 两条链路都使用系统根证书与平台策略校验，因此企业 TLS 中间盒下不会再出现「模型能调通、网关连不上」。
- **单连接多路复用**：桌面端与网关之间维持单一 WebSocket 长连接，各个车道与子代理通过 `subscribeId` 独立多路复用，避免连接泄漏。
- **历史按轮分页，一页索引 + 一轮正文**：打开一条会话先取最近一页索引（默认 20 条），每轮当场立起三形态（用户气泡 + 过程抬头 + 最终回复），随后只把**最新一轮**的 durable 帧读整轮换成展开形态；更早的轮次「加载更早」一次向前取一轮。打开成本因此是「一次索引 + 一轮帧」，不随轮数增长。
- **每轮读数随索引一起回来**：索引页为每条 Interaction 带上一行读数（用时、token 分桶、首字、速率、工具调用数），事实源是该轮自己的 `turn_metrics` 事件，与整条会话的累计投影同源。服务端按帧索引的交互指纹从尾部定向读取（每条交互通常只解压它自己的最后几帧），因此索引轮的分割线不必回放正文就能显示。没有指标事件的老记录退回「工作项终态时间差」给用时，其余字段留空。
- **展开才读整轮，收起即释放**：点开过程抬头才按 `interactionId` 读那一轮的 durable 帧并把过程正文整段换回来；收起会丢掉这些单元，正文随即失去引用。展开后的分割线仍以索引读数定稿，因为帧预算可能只读到尾窗。
- **首屏只读该交互的尾窗**：服务端按 `(session_id, interaction_id)` 定向取最后 1000 帧，一次往返落地即撤过渡面；升级前的老记录没有归属列，服务端在尾窗扫空时退回整会话扫描并保尾，界面不会看到空白。窗口起点之前被截掉的单元由渲染层折成一行提示，不再往回补正文。
- **生成中就有读数**：用量帧一到就立起（或刷新）这一轮的分割线，耗时随节拍走字；会话累计由网关基线加本视图增量合成，在跑的那一轮按增量计入，因此读数在生成过程中就在涨，不必等收口。
- **外部发起的新一轮由会话视图自己接管**：订阅是按 Interaction 建立的，后台作业跑完由 daemon 唤醒出来的新一轮、定时投递的一轮都不在订阅里。界面因此以车道快照上的 Interaction 总数为外部事实：总数增长且本视图没有在跑的轮次时重新接管一次（取最新一页并订阅那一轮）。本视图正在跑时增长出来的那一轮就是自己刚提交的那条，已经订阅在手，不重复接管。没有这条规则时正文会停在上一轮，而侧栏状态位与标题已按车道真实状态在走，表现成「作业早已结束，界面还在执行」。
- **历史帧页有独立的超时预算**：单页总超时 60 秒，而不是全站通用的 15 秒。超时与不可达是两句话：预算内没回来的报「网关响应超时」，只有连接层失败才报「网关不可达」，因为前者该等或该减少单页体量，后者才该去重启后台服务。
- **回放攒批投递**：实时帧与补齐帧仍按 16ms 窗口合并成一批再交给 WebView（批内保序、单批上限 512 帧），避免逐帧注入跟不上时丢帧、会话停在「生成中」；前端展开后仍按逐帧归约。
