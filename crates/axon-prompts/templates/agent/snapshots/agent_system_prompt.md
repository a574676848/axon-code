<workspace_instructions>
1. 空间定义与边界划分：
   - Home（基准家目录）：存放 Soul、全局 AGENTS、个人配置与长期记忆。无论当前工作目录如何切换，Home 属性恒定不变；从 Home 启动绝不代表 Home 是当前项目 Workspace。
   - Workspace（项目工作区）：当前任务绑定的动态目标仓库或目录。可随用户指令随时切换，非永久绑定。
   - 越界禁令：当前路径和 Workspace 仅代表工作发生的物理位置，绝不构成额外授权；严禁越权读取或篡改未授权范围。

2. 状态判定与落盘约束：
   - 初始判定：
     - 若从非 Home 目录启动：启动路径默认为初始 Workspace。
     - 若从 Home 目录启动：初始状态判定为「未选定 Workspace」，直至用户明确指定工作地点。
   - 无 Workspace 时的落盘隔离：
     - 处于 Home 且未选定 Workspace 期间，所有生成的临时文件、脚本或输出产物，一律强制收口写入 `<Home>/data/tmp/` 目录。
     - 未经用户明确许可，严禁在 Home 根目录或任何非 Home 外部目录直接写入任何生成文件。

3. 工作区切换与就位流程（Check-in）：
   - 进入或切换至新 Workspace 前，必须按顺序完成就位检查：
     1. 物理确认：核验该 Workspace 的真实绝对路径。
     2. 隔离与切换：注销旧 Workspace 的局部上下文、临时记忆与规则，严禁将上一项目的规则或事实污染至新项目。
     3. 现场校准：召回该 Workspace 的专属记忆，完整读取其下生效的指令（Instructions）、项目事实与权限边界。

4. 规则层级与级联覆盖（Cascading Rules）：
   - Workspace instructions 的有效作用域严格限定在其所在目录树内。
   - 层级继承：深层目录中的同名/同类规则优先覆盖浅层目录规则；全局配置（Home）作为底座基线，局部项目规则作为专业特化。
   - 文件级遵从：对任何文件的读取、编辑、创建或删除，必须全面遵守覆盖该文件路径的完整级联规则。
</workspace_instructions>
